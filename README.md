# AX거점 군 데이터 카탈로그 추천 — 첫 버전 (시연용)

AX거점에 방문한 기업·민간 연구자가 연구 목적을 적으면, 등록된 군 데이터 카탈로그 중 맞는 자료를 추천하는 한국어 웹 서비스다.
첫 버전 범위는 **연구 목적 입력 → 카탈로그 추천 → 추천 근거 확인**이다.

- 실제 군 데이터는 쓰지 않는다. 모든 카탈로그는 **시연용 가상 카탈로그**이며 화면에 그렇게 표시한다.
- AI(LLM·임베딩 모델)는 연결하지 않았다. **정해진 규칙으로 추천하며** 화면에 "AI 미연결"이라고 표시한다.

## 실행

Python 3.12 표준 라이브러리만 쓴다(외부 패키지 없음).

```bash
python run.py
```

브라우저에서 http://127.0.0.1:8765/ 을 연다. 로그인은 없다.
처음 실행할 때 `var/catalog.db` 가 만들어지고 가상 자료가 들어간다. 초기 상태로 되돌리려면 `var/` 폴더를 지운다.

## 카탈로그 목록(엑셀)

서비스는 **`data/catalogs.xlsx`** 의 카탈로그로 검색한다(`config.json` 의 `catalog_excel`).
지금 파일은 가상 카탈로그 44건으로 만든 견본이다. 실제 목록으로 바꾸려면 이 파일을 바꾸고 서비스를 다시 시작한다.
시작할 때 파일이 바뀌었으면 자동으로 다시 반영하고, 반영 결과를 콘솔에 출력한다.

- 한 행 = 카탈로그 하나, 첫 행 = 열 이름. 필수 열: **카탈로그 ID · 상태 · 제목 · 분야 · 공개 범위** (견본에서 주황색 머리글)
- 상태: `검수완료` = 검색에 나옴 / `검수대기` = 나오지 않음 / `철회` = 나오지 않음. 엑셀에서 지운 카탈로그는 철회된다.
- 목록형 칸(주제어·항목 정의·결합 식별자 등)은 세미콜론(;)이나 줄바꿈으로 구분. 주제어는 해시태그로 보인다.
- 빈 칸은 '미확인'으로 표시하고 추정하지 않는다.
- 열 이름이 달라도 흔한 이름은 알아본다(예: 카탈로그명·자료명 → 제목, 키워드·해시태그 → 주제어, 데이터 항목 → 항목 정의). 모르는 열은 무시하고 알려 준다.
- 날짜로 바뀐 칸(엑셀 일련번호)과 `2018.1`, `2018년 1월` 같은 표기는 `2018-01` 로 맞춘다.
- 추천 카드에 근거가 된 엑셀 위치(`catalogs.xlsx 19행 J열`)가 표시된다.
- `.xls`(옛 형식)는 읽지 못한다. 엑셀에서 `.xlsx` 로 다시 저장한다.

```bash
python tools/catalog_excel.py check data/catalogs.xlsx
```

`check` 는 반영하지 않고 검사만 한다(건너뛸 행·주의 사항 출력). 그 밖에:

| 명령 | 용도 |
|---|---|
| `python tools/catalog_excel.py export 새파일.xlsx` | 가상 카탈로그로 견본 엑셀 만들기 |
| `python tools/catalog_excel.py export 새파일.xlsx --current` | 지금 서비스 DB 의 카탈로그를 엑셀로 내보내기 |
| `python tools/catalog_excel.py import 파일.xlsx` | 다시 시작하지 않고 바로 반영(실행 중인 서버에도 적용) |

## 화면

| 화면 | 내용 |
|---|---|
| 첫 화면 | 서비스 이름·설명, 시연용 표시, 넓은 연구 목적 입력창, 눌러서 채우는 예시 6개(`data/examples.json`), "카탈로그 추천받기" |
| 추가 질문 | 결과를 바꿀 정보가 빠졌을 때만 선택지로 묻는다(`data/clarify_rules.json`). 답하지 않고 넘어갈 수도 있다 |
| 추천 결과 | 카드마다 ① 카탈로그명과 설명, 키워드 해시태그 최대 5개(등록된 주제어 → 분야 → 자료 유형 순, 예: #잔반 #1종) ② 포함된 주요 데이터 항목 ③ 연구 목적에 적합한 이유 ④ 활용 방법 ⑤ 부족한 정보·담당자 확인사항 ⑥ 이용 조건. "등록 정보 전체 보기"로 등록 메타데이터 전체를 확인 |
| 보류 | 맞는 자료가 없으면 추천하지 않고 그렇게 안내한다 |

## 추천이 작동하는 방식

1. **입력 정리** — 조사·어미를 한 번 떼고 불용어를 뺀다.
2. **조건 추출** — 용어사전과 낱말 목록으로 대상 분야, 분석 목표(예측·이상 탐지·분류·관계·추이), 자료 유형(이력·센서·통계), 기간을 찾는다.
3. **추가 질문** — 장비 고장 예측인데 이력/센서 방식이 없으면, 또는 분야가 없으면 묻는다.
4. **점수** — 키워드 일치(BM25, 45%) + 글자 조각 유사도(30%) + 조건 일치도(25%). 분야가 다르면 0.6배.
   0.40 이상 중 상위 5건을 고르고, 없으면 보류한다. 값은 `config.json`.
5. **근거 문장** — 등록된 값만 정해진 문장 틀에 넣는다(`app/explainer.py`).
   - 적합한 이유: 연구 목적의 낱말이 **실제로 들어 있는** 등록 항목을 인용하고, 일치한 낱말을 함께 적는다.
   - 활용 방법: 분석 목표 × 등록된 정답표시·자료 유형·항목에 따라 정한 문장.
   - 확인사항: 비어 있는(미확인) 항목, 결합 식별자, 등록된 이용 제한에서 만든다.

등록되지 않은 자료나 항목은 만들어 내지 않는다. 시험(`tests/test_public.py`)이 카드의 모든 인용 값과 주요 항목이 해당 카탈로그의 등록 값에 그대로 있는지 확인한다.

## 시험과 평가

```bash
python -m unittest discover -s tests -t .
```

```bash
python eval/run_eval.py --split all
```

평가 결과는 `reports/eval_report.md`. 시나리오의 기대 후보는 개발자가 쓴 점검용 값이므로, 전문가 판정으로 바꾸기 전에는 실적으로 보고하지 않는다.

## 구성

| 파일 | 역할 |
|---|---|
| `web/index.html`, `web/app.js` | 첫 버전 화면 |
| `app/server.py` | HTTP/JSON API. 첫 화면은 `/api/public/*` 만 쓴다 |
| `app/service.py` | 서비스 계층. 시연 방문자 범위(공개·거점승인, '제한' 제외)는 서버에서 강제 |
| `app/recommender.py`, `app/search.py`, `app/glossary.py` | 조건 추출·추가 질문·검색·순위 |
| `app/explainer.py` | 카드 근거 문장 생성과 인용 검증 |
| `data/catalogs.xlsx` | 서비스가 쓰는 카탈로그 목록(견본: 가상 카탈로그 44건) |
| `app/xlsx.py`, `app/excel_catalog.py` | 표준 라이브러리 .xlsx 읽기·쓰기, 엑셀 열 ↔ 카탈로그 항목 |
| `tools/catalog_excel.py` | 엑셀 검사·반영·내보내기 |
| `data/catalogs.json` | 견본 엑셀의 원본 가상 카탈로그(엑셀 파일이 없을 때 사용) |

## 후속 개발로 남긴 것

- 연구 방향 역제안, 가상 데이터 체험실, 수요 공백 분석, 신청서 생성
- 관리 기능: 이전 단계에서 만든 카탈로그 등록·검수·철회, 권한·로그·신고 관리 화면은 `/admin` 에 그대로 두었다(첫 화면에는 링크 없음, 로그인 필요, 시연 계정은 `data/users.json`). 첫 버전의 완료 범위에는 넣지 않는다.
- AI 연결: 임베딩 모델은 `app/search.py` 의 `SemanticEncoder`, LLM 문장 생성은 `app/explainer.py` 를 같은 출력 형식으로 바꾸면 된다. 바꿔도 인용 검증(`validate`)과 시험은 그대로 통과해야 한다.
